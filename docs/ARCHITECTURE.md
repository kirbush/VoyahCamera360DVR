# Архитектура и совместимость

## Видеопоток

Camera2 передаёт один поток в SurfaceTexture. GLES преобразует геометрию и выводит изображение в окно предпросмотра и, при записи, на входную Surface MediaCodec. H.264 упаковывается в MP4. Второй выход Camera2 для записи не требуется.

На исследованной системе Android 11 / API 30 приложение работает в ARM64, провайдер V4L2 — ARM32. Camera2 объявляет четыре входа. ID `1` выдаёт составной AVM-поток; ID `0`, `2`, `3` при отдельных восьмисекундных проверках не выдавали кадров. Объявленных наборов concurrent cameras нет. Это не доказывает невозможность другого способа независимого захвата.

| Режим источника | Полезная область | Область перспективной камеры |
| --- | --- | --- |
| Штатный 360 | 1920×720 | x=720…1920, 1200×720 |
| Парковщик APA | 1440×720 | x=560…1440, 880×720 |

Буфер транспорта может иметь размер 1920×1200, а Camera2 отдавать масштабированный кадр 1920×1080. Преобразование восстанавливает пропорции полезной области высотой 720 строк и сохраняет их при выводе. Выбор профиля источника находится в настройках.

Для исследованного ГУ требовалось отдельное исправление AVM-буфера в конфигурации и HAL. Это приложение его не устанавливает. Несовпадение конфигурации прошивки может приводить к отсутствию кадров или неверной геометрии.

## Выбор ракурса

Camera2 захватывает ракурс, выбранный AVM-контроллером. Переключение Camera2 ID не заменяет выбор передней или задней камеры.

В исследованной версии `EventManager::SendViewSelect` формирует десятибайтовую CIS-структуру: тип `0x1c`, длина `8`, значение `view << 1` в байте 6, остальные байты нулевые. `view=1` — передний 2D-ракурс, `view=2` — задний. Это структура управления производителя, а не идентификатор физического CAN-кадра.

ARM64 helper загружает `/system/lib64/libqg_hal.so` и вызывает `qg_canbus_open(void)`, `qg_canbus_control(int, char*)`, `qg_canbus_close(void)`. Принимаются только команды `front` и `rear`. Приложение проверяет контрольные суммы системных файлов и собственного helper, затем запускает helper через существующий `/system/xbin/su`. Ожидание ограничено четырьмя секундами.

Поддерживаемые системные файлы:

| Файл | SHA-256 |
| --- | --- |
| `dls_reverse_svr` | `88e65cdae3f3793156d000be26620d36a696a54b3073deb6c72d4595e548ee19` |
| `libqg_hal.so` | `87306b1bd0b1e189c702170186b4507e5128d8c431a902d5dc75ebe7f79c57a6` |

Прямой вызов исходной функции переключал задний ракурс на передний при скрытом штатном 360 без прекращения потока. Самостоятельный helper и его запуск с UID приложения требуют проверки на ГУ; обратное переключение пока выведено из той же таблицы команд. Успешная отправка запроса сама по себе не подтверждает фактический ракурс.

## Жизненный цикл и запись

Запуск открывает поток с сохранёнными настройками. Запись по умолчанию выключена. `onStop` завершает запись и освобождает камеру; потеря фокуса видимого окна не закрывает поток. Ошибки Camera2 освобождают ресурсы без бесконечного повторного захвата.

Отсутствие новых callback кадров в течение пяти секунд считается остановкой потока. При этом текущий MP4 завершается. Этот контроль не обнаруживает замороженную картинку внутри продолжающих поступать буферов.

Независимая двухканальная запись, фоновый сервис, циклическое хранение и сегментация не реализованы. Доступность потока при движении, после сна и холодного запуска требует проверки на конкретной прошивке.
